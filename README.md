# 课后邦企业官网与 CMS

企业官网，包含公司介绍、产品与服务、分类团队、公司动态和联系方式。课程使用详情弹窗，动态文章在新标签页打开原文。后台支持内容维护、文章草稿和发布，内容保存到本地文件，重启后保留。

## 交接入口

- [代码交接说明](docs/HANDOVER.md)：架构、目录、接口、数据结构、后台操作与交付边界。
- [Linux 部署与运维手册](docs/DEPLOYMENT.md)：安装、HTTPS、systemd、迁移、备份恢复、升级回滚和排错。
- [部署配置模板](deploy/)：Nginx、systemd 和环境配置示例，部署前替换示例域名与安装路径。
- 源码交接 ZIP 内含 `HANDOVER-MANIFEST.json`，记录准确的提交版本和逐文件 SHA-256；ZIP 旁的 `.sha256` 文件用于整包校验。

本次交接采用 **Linux + Node.js 24 LTS + Nginx + systemd 单进程**。交接包包含已提交源码、公开素材和公开内容快照，不含生产密码、未发布文章、完整运行数据库、日志和原始工作文件。现有完整数据须由持有人经私密渠道移交，按部署手册停服迁移。此交接不代表已在接手方服务器上线。

## 启动

生产部署使用仍获安全维护的 Node.js 24 LTS；没有第三方运行依赖，也没有构建步骤，不需要执行 `npm ci`。现有源码兼容较新的 Node.js 20，但 Node.js 20 已结束官方维护，不应作为新服务器的部署版本。[Node.js 官方版本状态](https://nodejs.org/en/about/previous-releases)

在项目根目录运行：

```powershell
npm start
```

官网：http://127.0.0.1:3000 ，后台：http://127.0.0.1:3000/admin 。默认仅监听本机。

首次启动生成随机初始密码；从旧版本升级时，原管理密钥可作为初始密码。读取方式：

```powershell
Get-Content .\data\admin-token
```

在后台输入初始密码后，先设置 15–128 个字符的新密码，再重新登录。`ADMIN_TOKEN` 只在尚无凭据文件时用于初始化，之后不会覆盖已设置的密码。成功改密后会删除本地初始密码文件；新密码仅以随机盐和 scrypt 哈希保存在 `data/admin-auth.json`，不会保存在浏览器存储中。

后台“账户安全”可随时修改密码。改密使所有设备的会话失效；退出登录使当前会话失效。会话闲置 30 分钟或登录满 8 小时后过期，重启服务也会使会话失效。未保存的编辑会在当前页面保留，重新登录后可继续保存。

忘记密码时，需要有服务器文件管理权限：先停止 CMS，确认实际 `DATA_DIR` 并保留内容和上传图片；从服务启动配置中移除 `ADMIN_TOKEN`，仅删除该目录下的 `admin-auth.json` 和 `admin-token`。重新启动会生成新初始密码，随后在后台立即改密。不要删除整个数据目录；认证文件只做私有备份，不上传到 GitHub。

## 内容维护

- 网站设置：品牌、首页文案、公司介绍、电话、邮箱、地址、备案信息。
- 产品与服务：分类、名称、副标题、详细介绍和服务要点。官网的服务卡片直接展示简介与服务要点，内容由后台统一维护，无需另开详情。
- 课程目录：按用户提供的《课后邦-课程手册(1).pdf》整理了 55 门课程，分为美育、益智、科技、劳动四类。官网每类在手机端先展示 3 门，电脑端先展示 6 门，支持展开全部；课程详情在站内弹窗中显示，无需打开或下载 PDF。后台可编辑课程名称、分类、卡片摘要、详细介绍及学习内容。课程摘要为官网改写，不作教学效果承诺；详细介绍根据用户粘贴的课程内容整理。
- 专业团队：姓名、职称、分类、简介。点击成员照片选择本机图片上传，支持 JPG、PNG、WebP，单张不超过 5 MB；预览确认后点击“保存并更新官网”。上传失败保留原照片。图片保存在 `data/uploads/`（设置 `DATA_DIR` 时随数据目录存储），备份时需一并保留。
- 公司动态：标题、分类、日期、摘要、纯文本正文、公众号原文链接及公开发布开关。
- 修改后点击“保存并更新官网”。未发布文章不会出现在公开 API 中。
- 团队分类自动从成员资料生成；列表顺序等于展示顺序。当前版本适合单管理员维护。

## 资料来源与待确认内容

文字及人物照片来自用户提供的团队介绍资料，首页首屏使用用户提供的室内环境照片。`reference/` 中的原始提取文件及本地截图不属于源码交接包。首页宣传语与服务分组是根据资料整理的官网文案，上线前应由企业确认。

动态文章的发布状态、标题和原文链接由后台维护；当前公开内容以 `backups/published-content.json` 快照为准。克隆仓库后首次启动默认使用 `data/seed.json`，不会自动导入这个快照；要恢复当前公开内容，应在新建空数据目录中按部署手册导入。

PPT 第 2、8、9 页对部分技术岗位有不同表述。首版将戴鹏标注为“技术研发团队”，待确认统一的职称。未使用个人服务经历作为公司整体业绩。

上线前补齐公司法定名称、对外联系方式、地址、备案资料、公众号内容，以及授权使用的案例资料；确认照片及公开职称。当前联系区没有提交表单，不会假装收集或发送咨询。

## 部署边界

当前项目可在本地运行，尚未部署到公网。生产环境需要域名、有效 HTTPS 证书、同机反向代理、持久化磁盘和私有备份。多管理员权限、多因素认证、操作审计和公众号自动同步尚未实现。

默认管理接口仅接受本机的 HTTP 请求。公网使用时设置 `PUBLIC_ORIGIN=https://你的实际域名`、`TRUST_PROXY=loopback`，Node 保持 `HOST=127.0.0.1`。同机反向代理负责 TLS，保留真实域名的 `Host`，覆盖 `X-Forwarded-Proto` 为实际协议。不要直接把 Node 端口暴露到公网。代理必须将 HTTP 重定向到 HTTPS；本项目不自动申请证书。来源域名、协议或转发配置不匹配时，管理接口会拒绝访问。

登录保护包括：scrypt（N=131072、r=8、p=1）加盐哈希、HttpOnly / SameSite=Strict 会话 Cookie（公网启用 Secure）、同源校验、写操作 CSRF 校验、单来源连续 5 次失败后冷却 15 分钟，以及全局请求和密码计算并发限制。反代模式以代理连接的 IP 进行限流，因此所有访问者共享该代理的失败额度；公网反代还应按真实客户端 IP 配置边缘限流。本进程内会话和限流适用于单实例，重启会清除它们。

传输加密依赖 HTTPS；密码哈希用于保护存储，不能替代 HTTPS。实现参考 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 和 [会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

还可设置 `PORT` 和 `DATA_DIR`。`data/content.json` 为运行内容；`data/seed.json` 仅用于首次初始化。静态服务只公开 `public/`，内容写入采用临时文件加替换方式。迁移时私下备份内容、上传图片和凭据文件，并设置仅服务账户可读写的目录权限；不要把密码、哈希、环境文件或未发布内容提交到公开仓库。

## 验证

官网支持课程详情弹窗、返回顶部以及微信、视频号、快手、抖音二维码放大查看。二维码使用用户提供的原图。

## GitHub 备份

按项目约定，在每次修改前和验证完成后提交、推送到 `weekomen/khfwcms`。执行 `node scripts/backup-content.mjs` 更新公开内容快照，再提交源码和素材。仓库为公开仓库，不包含管理密钥、未发布文章、临时文件及完整运行数据库。

恢复公开内容时，把 `backups/published-content.json` 复制到 `data/content.json`，把 `backups/uploads/` 中的图片复制到 `data/uploads/`；管理密钥由新环境重新生成。恢复前应保存原有运行数据。未发布文章需另行做私有备份。

## 自动检查

```powershell
npm test
```

验证内容校验、密码迁移、会话与 CSRF、登录限流、HTTPS 边界、草稿隔离、发布、重启持久化及私有文件不可访问。测试使用临时数据目录，不修改真实运行数据。

## 重新生成源码交接包

先更新公开快照，确认源码和文档已验证并提交，再执行：

```powershell
node scripts/create-handoff.mjs
```

打包需要 Git。脚本只导出当前提交中的受控公开文件，并检查快照没有未发布文章；未被当前公开团队引用的上传图片不会导出。输出位于本地 `handoff/<提交短编号>/`，包括 ZIP、清单和 SHA-256 校验文件，该目录不会推送到公开仓库。
